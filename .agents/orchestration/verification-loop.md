# AX-WMS 품질 검증 루프 (Verification Loop)

## 1. 자체 승인 방지 (Anti-Self-Certification) 원칙
- **원칙**: 코드를 작성하거나 수정한 에이전트는 결코 해당 작업의 "최종 승인" 또는 "완료 보고"를 직접 선언할 수 없습니다.
- **강제 루프**: 모든 코드 변경은 반드시 독립 검증관(`agy_verifier`)의 객관적인 검증 게이트를 거쳐야만 완료됩니다.

## 2. Verifier 게이트웨이 체크리스트

| 검증 단계 | 검증 항목 | 판정 기준 |
|---|---|---|
| **1. 계약 무결성** | Spring Boot DTO ↔ FastAPI Pydantic 모델 일치 | 필드명(CamelCase/Snake_case 매핑), 필수값/Optional 여부, HTTP 상태 코드 계약 일치 |
| **2. 테스트 자동화** | 백엔드 Gradle 및 AI pytest 스위트 | 100% PASS (회귀 실패가 없을 것) |
| **3. 컨벤션 게이트** | Javadoc 게이트 (SB-020 / ADR-023) | 신규/수정 helper, 정적 팩토리에 계약/WHY 중심 Javadoc 작성 여부 |
| **4. 변경 경계 검사** | 모듈 격리 원칙 | 타 모듈 파일 무단 변경 여부 확인 |
| **5. 보안 및 Git** | 비인가 Git 상태 변경 검사 | 사용자 명시적 동의 없는 커밋/푸시 시도 차단 |

## 3. 판정 및 재작업 루프
- **REJECTED 판정 시**:
  - `agy_verifier`는 실패 로그 및 구체적 결함 위치를 리포트에 기재하여 구현 에이전트(`agy_executor`)에게 재작업을 지시합니다.
  - 구현 에이전트(`agy_executor`)는 지적 사항을 수정한 후 다시 `agy_verifier`에게 검증을 요청합니다.
- **APPROVED 판정 시**:
  - 검증 증빙(테스트 로그, 체크리스트 통과 내역)을 포함한 최종 완료 보고서를 오케스트레이터 및 사용자에게 전달합니다.
