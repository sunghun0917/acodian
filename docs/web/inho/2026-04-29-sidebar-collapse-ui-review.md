# Sidebar 접힘 UI 수정 회고

  - `web/src/app/_common/store/ui.store.ts`

## 목적

Sidebar 접힘/펼침 UI를 추가하는 과정에서 정렬, 애니메이션, 색상 상태가 여러 차례 부자연스럽게 보였던 원인과 수정 방향을 기록한다.

## 잘 안 됐던 부분

### 1. layout grid 컬럼과 sidebar 내부 너비를 동시에 변경함

초기 구현에서는 protected layout의 grid 컬럼을 `17.5rem` / `4.75rem`으로 바꾸고, 동시에 sidebar 내부 row와 padding도 상태별로 바꿨다.

문제:

- 접을 때 sidebar가 잠깐 늘어나는 듯한 느낌이 생겼다.
- 바깥 layout과 내부 row가 동시에 재계산되어 전환이 자연스럽지 않았다.
- 아이콘 레일 위치가 상태별 padding 차이 때문에 미세하게 흔들렸다.

정리:

- layout은 `flex` shell로 단순화한다.
- 실제 접힘/펼침 애니메이션 주체는 `aside` 하나로 둔다.
- `width`, `min-width`, `max-width`, `flex-basis`를 같은 값으로 묶어 flex 재계산 흔들림을 줄인다.

### 2. 접힌 상태와 펼친 상태의 내부 padding이 달랐음

접힌 상태는 `px-2`, 펼친 상태는 `px-3`처럼 서로 다른 padding을 사용했다.

문제:

- 메뉴 아이콘이 접힘/펼침 전환 중 좌우로 미세하게 움직였다.
- 사용자는 "간격이 조금 변한다"는 느낌을 받았다.

정리:

- sidebar 내부 기준 padding은 상태와 무관하게 통일한다.
- 아이콘 레일은 항상 같은 폭을 사용한다.
- 현재 기준은 `3.75rem` 레일이다.

### 3. 일반 메뉴와 접이식 메뉴의 row 구조가 달랐음

일반 메뉴는 `Link`, 접이식 메뉴는 `button`이라 기본 스타일과 flex/grid 계산이 달랐다.

문제:

- `업무일지`, `조직` 같은 접이식 메뉴 라벨이 가운데로 밀려 보였다.
- 일반 메뉴와 접이식 메뉴의 텍스트 시작점이 다르게 보였다.

정리:

- 모든 row는 같은 grid 구조를 사용한다.
- 펼친 상태: `3.75rem / minmax(0,1fr) / action`
- 접힌 상태: `3.75rem` 단일 컬럼
- `button` row에는 `text-left`를 명시해 브라우저 기본 정렬 영향을 없앤다.

### 4. 숨긴 텍스트가 여전히 레이아웃에 영향을 줌

텍스트를 `opacity-0`, `max-width: 0`으로만 숨기려 했다.

문제:

- 접힌 상태에서도 숨긴 텍스트/chevron이 암묵적으로 레이아웃 계산에 영향을 줄 수 있었다.
- active 배경 컨테이너가 아이콘보다 크게 잡히거나 어색하게 보였다.

정리:

- 접힌 상태에서는 텍스트와 chevron을 렌더링하지 않는다.
- 접힌 row는 실제로 `3.75rem` 단일 컬럼만 갖게 한다.

### 5. 메뉴 아이콘을 감싸는 외부 박스가 시각적으로 무거웠음

아이콘마다 `rounded` 배경 박스가 있었다.

문제:

- 접힌 상태에서 아이콘 레일이 답답하게 보였다.
- active 배경과 아이콘 배경이 겹쳐 계층이 과해졌다.

정리:

- 메뉴 아이콘 외부 컨테이너 배경은 제거한다.
- 선택 상태는 row의 배경 컨테이너로만 표시한다.

### 6. 탭 색상 상태가 중구난방으로 보였음

active, inactive, open group, sub menu가 서로 다른 `text-white/*` 값을 사용했다.

문제:

- 현재 선택된 탭만 흰색이어야 한다는 기준과 다르게 보였다.
- 실제 화면에서는 일부 inactive 메뉴가 active처럼 선명하게 보였다.
- 결국 색상보다 배경 컨테이너로 선택 상태를 구분하는 편이 더 명확했다.

정리:

- sidebar 메뉴 글자와 아이콘은 전부 `text-white`로 통일한다.
- 선택 여부는 `bg-white/10` 같은 배경 컨테이너로만 구분한다.

### 7. 하단 프로필 영역이 메뉴 row와 다른 구조였음

프로필 링크와 로그아웃 버튼을 같은 flex/grid 흐름 안에서 배치했다.

문제:

- 접힘/펼침 중 `김이사` 텍스트 위치가 미세하게 움직였다.
- 다른 메뉴 row는 안정적인데 프로필 영역만 따로 흔들렸다.

정리:

- 프로필 영역도 메뉴와 같은 아이콘 레일 기준을 사용한다.
- 로그아웃 버튼은 프로필 링크 레이아웃 계산에서 분리한다.
- 접힌 상태에서는 로그아웃 버튼을 숨기고 프로필 아이콘만 표시한다.

## 다음 구현 기준

- 접힘/펼침 애니메이션의 주체는 하나만 둔다.
- sidebar 내부 x좌표 기준은 상태별로 바꾸지 않는다.
- 모든 메뉴 row는 같은 layout template을 공유한다.
- 접힌 상태에서 필요 없는 텍스트/액션은 렌더링하지 않는다.
- active 여부는 배경 컨테이너로 표시하고, 텍스트 색상으로 상태를 복잡하게 나누지 않는다.
- 프로필, 브랜드, 일반 메뉴, 접이식 메뉴 모두 같은 아이콘 레일 기준을 따른다.

## 최종 방향

Sidebar 접힘 UI는 "펼친 메뉴를 좁게 압축하는 UI"가 아니라 "같은 아이콘 레일을 유지한 채 바깥 폭만 줄이는 UI"로 다루는 것이 맞다.

따라서 구현 기준은 다음과 같다.

- `aside`: 실제 width transition 담당
- 내부 컨텐츠: 고정된 아이콘 레일 기준 유지
- collapsed row: 아이콘 단일 컬럼
- expanded row: 아이콘 / 텍스트 / 액션 컬럼
- 선택 상태: row background로만 표현
