# Naive RAG·Mix 정량 평가 및 개선 결과

> **결론: 관계 질문의 근거 누락은 크게 줄었지만, 본문 질문의 전반적 성능 향상은 확인하지 못했다.**
> 이번 개선은 **Mix + DB 관계 보완**이다. 그래프 검색 자체가 좋아졌거나 운영 서비스 성능이 검증됐다는 뜻은 아니다.

최종 편집: 2026-09-27 · 평가 대상 50문항 · 5개 실험 조합 · 결과 250개

## 1. 한눈에 보는 결과

- **관계 질문:** Mix의 Context Recall이 **0.1833 → 1.0000**, Answer Relevancy가 **0.4857 → 0.8645**로 상승했다.
- **본문 질문:** 근거 회수는 소폭 개선됐지만 Faithfulness·Factual F1은 하락했다. 일괄 적용 근거는 부족하다.
- **실제 오류 수정:** 선행업무의 팀 대신 현재 업무의 팀을 답하거나, 선행업무의 팀을 찾지 못하던 사례가 개선됐다.
- **평가 자체의 한계:** 관계 질문의 청크 Precision은 개선 후에도 0이다. 관계 문맥이 이 지표의 입력에서 제외되므로 관계 보완 효과를 측정하지 못한다.
- **적용 상태:** 평가용 구현·테스트·실험 완료. **운영 API에는 미적용**이며 권한 필터 검증이 선행돼야 한다.

## 2. 기존 대비 얼마나 좋아졌나?

아래 값은 문항별 점수의 산술평균이다. 기존은 최초 보고서 점수가 아니라 **기존 답변·문맥을 그대로 재채점한 대조군**이다.
답변 불가 5문항은 평균에서 제외하고 거절 성공 여부로 별도 평가했다.

**개선 Mix는 Mix + DB 관계 보완을 뜻한다.** 굵은 숫자는 각 행의 최고점이며, 증감은 반올림 전 원점수 기준이다.

### 본문 질문 · 35문항

| 평가 지표 | Naive | Mix | 개선 Mix | 증감 |
|:---|---:|---:|---:|---:|
| 근거 충실도 | **0.9905** | 0.9829 | 0.9733 | −0.0095 |
| 답변 관련성 | 0.8677 | 0.8926 | **0.8959** | +0.0033 |
| 청크 정밀도 | **0.6163** | 0.5975 | 0.6029 | +0.0054 |
| 근거 재현율 | **1.0000** | 0.9714 | 0.9857 | +0.0143 |
| 사실 일치 F1 | **0.4763** | 0.4669 | 0.4486 | −0.0183 |

**해석:** 일부 지표는 개선됐지만, 본문 질문의 전반적인 성능 향상은 확인되지 않았다.

### 관계 질문 · 10문항

| 평가 지표 | Naive | Mix | 개선 Mix | 증감 |
|:---|---:|---:|---:|---:|
| 근거 충실도 | 0.7650 | 0.8300 | **0.9467** | +0.1167 |
| 답변 관련성 | 0.1498 | 0.4857 | **0.8645** | +0.3789 |
| 청크 정밀도¹ | 0.0000 | 0.0000 | 0.0000 | 0.0000 |
| 근거 재현율 | 0.0000 | 0.1833 | **1.0000** | +0.8167 |
| 사실 일치 F1² | 0.0570 | 0.0830 | **0.4610** | +0.3780 |

**해석:** 관계 정보를 보완하면서 근거 재현율과 답변 관련성이 크게 상승했다.

¹ 청크 정밀도는 추가 관계 문맥을 평가하지 않아 관계 보완 효과를 반영하지 못한다.  
² 사실 일치 F1은 자동 채점 지표이며 실제 정답률과 다르다.

지표 대응: 근거 충실도 = Faithfulness · 답변 관련성 = Answer Relevancy · 청크 정밀도 = Context Precision · 근거 재현율 = Context Recall.

**읽는 법:** 모두 높을수록 좋은 방향의 지표지만, 서로 다른 대상을 측정하므로 하나의 평균으로 합치지 않았다.
Context Recall 1.0은 평가 문맥에 기준답변 근거가 충분하다는 판정이지, 실제 답변 정답률 100%가 아니다.
Factual F1 역시 아래 사례처럼 채점 오류·기준답변의 정보량에 영향을 받아 실제 정답률로 해석하면 안 된다.

## 3. 무엇이 문제였고, 무엇을 고쳤나?

| 구분 | 확인된 문제 또는 한계 | 이번 조치 | 판정 |
|---|---|---|---|
| 코드: 문맥 구성 | 출처 표시용 anchor가 본문 청크 자리를 차지함 | 같은 업무 ID의 원문으로 치환하고 중복 제거 | 개선 variant 잔존 anchor 0개 |
| 코드: 관계 근거 전달 | 선행업무는 있어도 그 업무의 소속 팀·이름이 문맥에 빠짐 | 검색된 업무에서 직접 관계를 읽고 이름·팀 보완 | 관계 edge recall 0.4500 → 1.0000 |
| 데이터 활용 | 본문만으로는 확정 등록 관계를 답할 수 없음 | 본문 유사성 대신 DB의 확정 관계 사용 | 단순 본문 추가보다 관계 정보 전달이 중요 |
| 벤치마크 구성 | 본문 35개와 관계 10개의 필요한 정보가 다름 | 범위별 평균 분리 | Naive의 관계 점수만으로 전체 모델 열세를 단정할 수 없음 |
| 평가 입력 | CP는 청크만 평가하고 CR·Faithfulness는 관계를 포함한 문맥 평가 | 지표 입력 차이를 명시, 관계 회수 보조 지표 병기 | 관계 질문 CP 0을 관계 검색 정확도 0으로 읽으면 안 됨 |
| LLM 채점 | 부분 근거를 무용하다고 판단하거나 답변의 주어를 잘못 분해함 | 실제 judge trace 확인 및 사례 기록 | 점수만으로 정답 여부를 확정할 수 없음 |

**판단:** 하나만의 문제가 아니다. 이번 실험에서 가장 뚜렷하게 개선된 것은 **코드의 문맥 구성·관계 전달 문제**다.
한편 낮은 점수의 일부에는 **벤치마크 기준답변과 자동 채점 방식의 한계**가 섞여 있다.
전체 원천 데이터의 관계 정확성까지 독립 검증한 것은 아니므로 “데이터에는 문제가 없다”고 단정하지 않는다.

## 4. 실제 답변은 어떻게 바뀌었나?

아래 답변 비교는 저장된 응답의 핵심 내용을 요약한 것이다.


### graph-005

**질문:** 「창고별 수량 편차 관련 1차 확인 요청」에 코퍼스 안에서 직접 선행업무로 등록된 업무의 제목과 그 선행업무의 소속 팀은 무엇인가? 제목 유사성이 아니라 등록 관계를 기준으로 답해 줘.

**기준답변:** 직접 선행업무는 「운영 체크리스트 누락 원인 분석」이며, 그 선행업무의 소속 팀은 삼성전자 DX 플랫폼 운영 TF이다.

### 정답을 포함했는데 Factual F1이 0인 사례: graph-010

개선 답변은 선행업무를 **「인증 실패 로그 분석 보정 작업 진행」**, 팀을 **계정·권한 하드닝 TF**로 제시해 기준답변의 요구사항을 충족했다. 하지만 Factual F1은 **0.0**이었다.

다만 문맥 변환에 따른 포맷·길이 변화와 LLM 변동도 포함돼 있으므로 모든 상승분을 하나의 수정에 엄밀히 귀속하지 않는다.

| 항목 | 확인 결과 |

| 정보 누출 검사 | 검사한 보정 경로에 질문·정답·category·정답 ID를 전달하지 않음. gold는 평가에만 사용 |
| 모드 분리 | Naive 100개 결과에 추가 관계 레코드 없음 |
| 테스트·리뷰 | 작업 중 실행한 AI 테스트 164개 및 평가 테스트 27개 통과. 코드 리뷰 APPROVE |
| 독립 결과 검토 | 집계·파일 무결성·문맥 일치 확인. snapshot 실물과 일반화 검증은 미충족 |

**반드시 남겨야 할 한계**

1. **실시간 검색 실험이 아니다.** 기존 검색 결과를 재생해 후처리 문맥을 비교했다. 재검색·재인덱싱·운영 E2E 속도 개선은 검증하지 않았다.
2. **독립 holdout이 없다.** 개발용 50문항으로 개선·평가했다. 반복 실행과 통계적 유의성 검정도 수행하지 않았다.
3. **채점 변동이 있다.** 답변 가능한 Naive 45문항은 anchor 보정 전후 문맥·응답이 동일하지만 점수가 변했다. 이 차이는 검색 개선이 아닌 재채점 변동이다. 전체 50문항 중 응답 재사용은 49개다.
4. **snapshot 영구 보존은 미충족이다.** full_docs·DB 조회 결과를 실행 중 메모리에서 고정하고 해시를 기록했으나 실물 snapshot 파일을 별도 저장하지 않았다. 오프라인 완전 재현을 보장하지 않는다.
5. **생성·채점 모델이 같다.** 자기평가 편향이 가능하며, 자동 점수와 사람의 정답 판정을 구분해야 한다.
6. **운영 권한 검증이 남았다.** 평가 scope의 필터가 운영 인증·인가를 대신하지 않는다. 기본 API 연결은 보류했다.

## 8. 다음 개선 우선순위

| 우선순위 | 작업 | 완료 판단 기준 |
|---|---|---|
| 1 | 제목·팀·관계 방향을 분리한 구조화 정답 평가 추가 | 수동 검토한 정답/오답 사례와 항목별 자동 판정 비교 |
| 2 | 관계가 필요한 질문에만 보완 적용하는 방식 검증 | 독립 본문·관계 평가셋에서 본문 회귀 없이 관계 개선 재현 |
| 3 | 재현용 snapshot을 접근 통제된 위치에 보존 | 원천 실물과 해시를 대조하고 동일 입력 재실행 가능 |
| 4 | 독립 holdout·반복 채점 | 평균뿐 아니라 분산·신뢰구간 및 category별 실패 사례 보고 |
| 5 | 운영 scope·권한 필터 연결 후 실제 검색 검증 | 교차 팀 정보 누출 방지 테스트, E2E 품질·지연 측정 통과 |

**최종 판단:** 관계 근거를 전달하는 방식의 개선은 유효한 후보로 확인됐다. 다만 현재 결과만으로 모든 질문에 적용하거나 운영 성능 향상을 확정해서는 안 된다.
