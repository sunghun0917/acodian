## 독립 검토와 보완
benchmark-evaluator는 중간 80문항을 원천 SQL과 독립 대조하여 인용·관계·정답 집합 불일치 0, split 근거 중복 0을 확인했다.
다만 이후 최종 파일 분리·질문 정리는 해당 에이전트가 재확인하지 못해 독립 판정은 PARTIAL이다.

발견한 사항은 메인이 최종 파일에서 확인했다.
- v2-067: 같은 제목인 시작 업무 174와 선행업무 172를 구분하도록 기준답변에 정답 업무 ID를 병기했다. 정답 reference에 172 존재/174 미포함 확인.
- v2-019: 단순사실 반복 패턴을 줄이기 위해 운영 영향·잔여 리스크 관련 새 문항으로 교체했다.
- 신규 질문의 날짜 조건을 기존 본문에 있는 제목·시작 업무 ID로 바꿨다.
- 최종 파일의 4필드/ID join/원천 근거/전체 선행 집합/부재/split을 메인이 별도 스크립트로 재검증했다.

## 해석 제한
- 기존 합성 200건을 재사용한다. 단순사실 15개도 V1 재사용이며 새로운 독립 코퍼스 holdout은 아니다.
- 실제 그래프에 분기·순환이 없고 최대 깊이는 4다. 해당 복잡 구조는 실데이터 평가 대상이 아니다.
- 제목·시작 업무 ID를 알려주는 질문이 있어 대상 식별 난도가 낮다.
- 기존 Naive 본문과 Mix의 그래프 정보 접근 차이를 포함하는 시스템 구성 비교다.
- 부재 8문항은 등록 관계가 없는 사실을 확인하는 문항이지 일반 답변 불가/환각 거절 평가가 아니다.
- 이 데이터셋 검증 단계에서는 실제 인덱싱, RAGAS 실행, API 호출, 운영 변경, 커밋 및 push를 수행하지 않았다.
