# V3 Naive / 기본 Mix — RAGAS 정량 비교

> 과거 5지표 탐색 비교 기록이다. 현행 주평가 3지표와 제외 사유는 [report.md](report.md)를 참조한다.

## 실행 및 검증

- 2026-09-29 KST. **50문항 × 두 모드 = 100개 응답, 500개 유효 점수, 생성·채점 오류 0건.**
- 생성: `gemini-3.5-flash-lite`, 평가: `gemini-3.8-flash`, 임베딩: `gemini-embedding-001`, RAGAS 0.4.3.
- LightRAG v3 내부 `aquery_llm` 검색 → 실제 검색 문맥으로 Gemini 답변 생성 → RAGAS 채점. FastAPI HTTP 부하 시험은 아니다.
- Mix 내장 그래프 검색만 사용. 추가 다중홉 확장·PostgreSQL 관계 보완·anchor 치환·reranker 모두 OFF.
- 동일 프롬프트, temperature=0, top_k=10, chunk_top_k=5. 응답 캐시 OFF, 키워드 캐시는 재사용.
- 고정 200건·선행관계 77개를 확인했다. 평가 전후 로컬 원문/처리 상태, Neo4j 관계, Qdrant payload가 일치했다. 수치 벡터 자체는 별도 검증하지 않았다.
- 정답은 검색·생성에 전달하지 않았다. 100건 모두 생성 프롬프트의 문맥과 RAGAS 입력 문맥이 일치한다.

## 전체 평균

0~1 점수, 각 모드 n=50. 단일 종합 점수로 합산하지 않는다.

| 지표 | naive | mix | mix − naive |
|---|---:|---:|---:|
| Faithfulness (근거 충실도) | 0.8833 | 0.9392 | +0.0558 |
| Answer relevancy (답변 관련성) | 0.2837 | 0.7764 | +0.4927 |
| Chunk precision (본문 청크 정밀도) | 0.3658 | 0.3228 | -0.0431 |
| Context recall (문맥 재현율) | 0.4750 | 0.6250 | +0.1500 |
| Factual F1 (해석 주의) | 0.2924 | 0.0812 | -0.2112 |
| 검색+생성 평균 시간 | 2.293초 | 4.578초 | +2.285초 |

## 유형별 결과

각 셀은 naive → mix. 전체 지표와 development/evaluation 각 25문항의 분리 집계는 [자동 보고서](report.md)에 있다.

## 해석과 한계

- 이번 실행에서 Mix는 근거 충실도·답변 관련성·문맥 재현율이 높았다. 본문 청크 정밀도는 낮고 검색+생성 시간은 약 2배였다.
- 단순 사실은 두 모드의 문맥 재현율이 1.0으로 같고, 답변 관련성과 청크 정밀도는 naive가 소폭 높았다. 관계 질문에서는 Mix의 관련성·재현율이 높았다.
- 높은 관련성·근거 충실도가 올바른 대상 업무 식별이나 관계 정답을 보장하지 않는다. **정답 정확도가 개선됐다고 단정하지 않는다.**
- Chunk precision은 본문 청크 순위만 평가하며 그래프 검색 정밀도가 아니다. 관계 부재는 정보 부족 거절과 다른, 검증 가능한 빈 관계 정답이다.
- naive는 본문, mix는 본문+등록 그래프를 사용한다. 정보량이 다른 시스템 구성 비교이지 순수 그래프 알고리즘 효과 분리가 아니다.
- 동일 합성 코퍼스 재사용·연관 문항·단일 채점이라는 한계가 있다. 독립 holdout이나 50개 독립 표본의 통계적 우열을 주장하지 않는다.
- 지연은 RAGAS 채점을 제외한 검색+생성 시간이다. 키워드 캐시·API 변동·별도 2건의 진단 호출 영향을 포함할 수 있다. 운영 HTTP 지연이나 총 비용을 측정하지 않았다.

## Factual F1 주의: 원점수를 보존하되 정답률로 사용하지 말 것

원점수는 naive 0.2924, mix 0.0812다. 이 결과를 숨기거나 교체하지 않았다. 다만 짧은 기준답변이 생략한 질문 맥락 때문에 감점된 사례를 확인했다.

- `v3-001--naive`: 답변은 화면·로그·지난 메모라는 기준 사실을 포함하지만, NLI는 기준답변에 없는 “P0 회귀”, “오전”, 업무일지 ID 때문에 답변의 모든 claim을 미지원으로 판정했다.
- `v3-002--mix`: 기준 시작 시점과 비교 시점을 나눠 확인했다는 핵심 사실은 일치하지만, NLI는 기준답변에 “매장 주문 취소”라는 질문 맥락이 없다는 이유 등으로 감점했다.
- `FactualCorrectness.ascore(response, reference)`는 질문을 입력받지 않는다. 이는 한국어 이해 실패라는 추측이 아니라 실제 NLI reason에서 확인한 기준답변의 맥락 누락 문제다.
- 진단 2건은 별도 재호출이며 원점수는 바꾸지 않았다. **전체 낮은 점수가 모두 채점 문제라는 의미는 아니며 실제 오답 가능성도 남는다.**
- 포트폴리오에는 관측값과 한계를 함께 제시한다. 관계 정답률을 주장하려면 시작 업무·관계 방향·최종 엔티티·선행 집합을 고정된 별도 기준으로 채점해야 한다.

진단 근거: [factual-correctness-audit.json](factual-correctness-audit.json).

```powershell
ai/.venv/Scripts/python.exe -B -X utf8 docs/ai/evaluation/v3/run_evaluation.py --output docs/ai/evaluation/v3/results-judge-gemini-3.8-flash-20260929 --report-only
```
