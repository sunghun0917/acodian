# iBank Dummy Data Preferences

## Fixed preferences from user
- 공통 원문 비밀번호: `password1!`
- `tb_user.password_hash`는 **공통 BCrypt 해시값** 사용
- 현재 고정 해시값: `$2b$12$tzatvdD02DDLmrqIXLtCa.ucFmjdnydHO73TWemkBYQSHVAUnYNXW`
- 이메일/전화번호는 전체적으로 일관된 규칙을 따르되, 일부만 약간 다르게 섞어 실제 데이터처럼 보이게 구성
- 목표 팀 수: 최소 10개 이상
- 최종 산출물: `.sql` 파일
- 핵심 목표: 생성된 팀/워크로그를 기반으로 시멘틱 검색 정합성을 평가할 수 있을 정도로 양질의 자연어 데이터 확보
- `tb_user.title_name`은 조직상 직책만 담는다: 1번은 `본부장`, 2~4번은 `사업부장`, 5~35번은 모두 `팀원`
- `tb_user.position_name`은 직급만 담는다: `사원`, `대리`, `과장`, `차장`, `부장`, `상무`, `이사` 중 하나
- TF 팀장 경험은 `title_name`을 바꾸지 않고 `tb_user_team.is_leader`와 `team_role`로 표현
- 35명 규모 더미 조직에서는 실무자 직급을 과하게 올리지 않는다. 5~35번은 `사원`/`대리`/`과장` 중심, `차장`은 소수, `부장`은 특별 요청이 없으면 지양

## Quality direction
- 단순 패턴 반복보다, 실제 조직 안에서 이어지는 업무 흐름이 드러나야 함
- 같은 키워드라도 팀/시점/작성자 성격에 따라 다른 문맥으로 나타나야 함
- 재발 이슈, 지연 완료, 타 부서 협업, 승인/검토, 보고 흐름이 자연스럽게 섞여야 함
- 사용자별 성격 차이가 문장 길이, 강조 포인트, 표현 습관에 반영되어야 함

## Password policy note
- BCrypt는 보통 salt 때문에 사용자마다 해시가 달라질 수 있지만, 이번 더미 데이터는 **공통 로그인값 재현**을 위해 동일 해시를 전 사용자에 재사용한다.
- 따라서 `password1!` 입력 시 모든 더미 계정이 같은 BCrypt 해시로 검증되는 형태를 가정한다.
